# HTTP API

Все маршруты имеют префикс `/api/v1`. Входные и выходные данные передаются
в JSON. Значения ограничений ниже соответствуют текущим HTTP-схемам.

Все маршруты `/campaigns`, `/offers`, `/references` и `/operations` требуют заголовок
`Authorization: Bearer <API_ACCESS_TOKEN>`. Для `POST /campaigns` также нужен
уникальный `Idempotency-Key` длиной от 16 до 128 символов. Повтор с тем же
ключом и телом возвращает сохранённый ответ; повтор с другим телом или пока
первый запрос ещё выполняется получает `409`. См. [доступ к API](security.md).
Завершённые ключи хранятся 30 дней. Ключ, который остаётся pending больше часа,
переходит в stale; перед `DELETE /operations/idempotency/{key}` оператор должен
вручную проверить в Keitaro, была ли кампания создана.

## Состояние и справочники

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/v1/health` | Проверить подключение к базе данных |
| `GET /api/v1/references` | Получить домены, группы кампаний и источники трафика |
| `GET /api/v1/offers?search=&limit=20` | Найти офферы; `limit`: от 1 до 100 |
| `GET /api/v1/operations` | Последние 50 записей аудита |
| `DELETE /api/v1/operations/idempotency/{key}` | Снять stale-резервацию после проверки результата в Keitaro |

Поиск офферов выполняется без учёта регистра по имени и ID.

## Кампании

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/v1/campaigns?search=` | Найти кампании по имени с постраничной загрузкой из Keitaro; поиск возвращает до 500 совпадений |
| `POST /api/v1/campaigns` | Создать кампанию и настроенный набор потоков; ответ `201` |
| `GET /api/v1/campaigns/{campaign_id}` | Получить кампанию и её потоки |

При чтении кампании потоки сверяются с Keitaro и локально сохранёнными
черновиками. В ответе поток содержит `offers`; каждый оффер включает текущие
поля `share` и `state`, опубликованные `published_share` и `published_state`,
черновые `draft_share` и `draft_state`, а также `is_pinned`, `is_deleted` и
`has_draft`.

Тело `POST /api/v1/campaigns`:

```json
{
  "name": "Spring campaign",
  "geo": "US",
  "offer_id": 42,
  "domain_id": 1813,
  "group_id": 10332,
  "source_id": 836
}
```

Обязательны `name`, `geo` и положительный `offer_id`. `geo` — код страны
ISO 3166-1 alpha-2; пробелы удаляются, код приводится к верхнему регистру.
`domain_id`, `group_id` и `source_id` можно не указывать: тогда применяются
значения по умолчанию из конфигурации.

## Офферы потока

| Метод и путь | Назначение |
| --- | --- |
| `POST /api/v1/campaigns/{campaign_id}/streams/{stream_id}/offers` | Добавить оффер в локальный черновик; ответ `201` |
| `DELETE /api/v1/campaigns/{campaign_id}/streams/{stream_id}/offers/{offer_id}` | Пометить оффер удалённым в черновике |
| `POST /api/v1/campaigns/{campaign_id}/streams/{stream_id}/offers/{offer_id}/restore` | Восстановить удалённый оффер в черновике |
| `POST /api/v1/campaigns/{campaign_id}/streams/{stream_id}/push` | Проверить черновик и опубликовать его в Keitaro |
| `POST /api/v1/campaigns/{campaign_id}/streams/{stream_id}/draft/cancel` | Отменить черновые изменения потока |

Тело добавления:

```json
{
  "offer_id": 42
}
```

Добавление, удаление и восстановление меняют локальный черновик и не отправляют
изменения в Keitaro. Доли активных офферов пересчитываются так, чтобы их сумма
составляла 100%; доли закреплённых офферов остаются неизменными. Удаление можно
отменить восстановлением или отменой всего черновика. Push не выполняется, если
нет активных офферов или их доли не дают 100%. Изменять офферы можно только в
потоке, который их использует. Нельзя добавить дубликат или удалить отсутствующий
оффер.

Ответ потока показывает опубликованные и черновые доли раздельно. После
успешного `push` поля отправленных офферов совпадают с опубликованными;
удалённые офферы остаются локальными записями для восстановления. Черновой
оффер, который ещё не был опубликован и затем удалён, отбрасывается при отмене
черновика. API также аудирует добавление, удаление, восстановление, push и
отмену.

## Ошибки

| HTTP | Смысл |
| --- | --- |
| `404` | Кампания, поток или оффер не найден |
| `409` | Операция конфликтует с текущим состоянием |
| `422` | Ошибка валидации входных данных FastAPI/Pydantic |
| `502` | Ошибка или некорректный ответ Keitaro |
| `429` | Слишком много неудачных попыток авторизации; см. `Retry-After` |

Ошибки имеют форму `{"detail": "..."}`.
