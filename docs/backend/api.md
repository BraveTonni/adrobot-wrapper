# HTTP API

Все маршруты имеют префикс `/api/v1`. Входные и выходные данные передаются
в JSON. Значения ограничений ниже соответствуют текущим HTTP-схемам.

Все маршруты `/campaigns`, `/offers`, `/references` и `/operations` требуют заголовок
`Authorization: Bearer <API_ACCESS_TOKEN>`. Для `POST /campaigns` также нужен
уникальный `Idempotency-Key` длиной от 16 до 128 символов. Повтор с тем же
ключом и телом возвращает сохранённый ответ. Завершённые ключи хранятся 30
дней. См. [доступ к API](security.md).

## Состояние и справочники

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/v1/health` | Проверить подключение к базе данных |
| `GET /api/v1/references` | Получить домены, группы кампаний и источники трафика |
| `GET /api/v1/offers?search=&limit=20` | Найти офферы; `limit`: от 1 до 100 |
| `GET /api/v1/operations` | Последние 50 записей аудита |
| `POST /api/v1/catalog/refresh` | Принудительно перечитать офферы и справочники из Keitaro |
| `DELETE /api/v1/operations/idempotency/{key}` | Снять stale-резервацию после проверки результата в Keitaro |

Поиск офферов выполняется без учёта регистра по имени и ID.

`GET /api/v1/operations` возвращает список записей аудита с `id`, временем
`created_at`, действием `action`, исполнителем `actor`, `entity_type` и
`entity_id`, связанными `campaign_id`/`stream_id`, статусом, `detail`, JSON
полями `before_payload` и `after_payload`, а также `error`. Для `actor`
используется нормализованный заголовок `X-User`, иначе IP клиента; если адрес
недоступен, значение равно `unknown`. Новая запись сначала имеет статус
`pending`, затем получает итог операции.

## Кампании

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/v1/campaigns?search=` | Найти кампании по ID или части названия; ответ содержит до 500 совпадений |
| `POST /api/v1/campaigns` | Создать кампанию и настроенный набор потоков; ответ `201` |
| `GET /api/v1/campaigns/{campaign_id}` | Получить кампанию и её потоки |

Числовой `search` открывает кампанию с этим ID. Текстовый поиск читает кампании
Keitaro страницами по 100, пока не наберётся 500 совпадений, не закончится
список или не будут просмотрены 2000 последних кампаний: Admin API не умеет
фильтровать по названию сам.

При чтении кампании потоки сверяются с Keitaro и локально сохранённым
снимком. В ответе поток содержит `offers`; каждый оффер включает название
`name`, текущие поля `share` и `state`, опубликованные `published_share` и
`published_state`, черновые `draft_share` и `draft_state`, а также `is_pinned`,
`is_deleted` и `has_draft`.

Тело `POST /api/v1/campaigns`:

```json
{
  "name": "Spring campaign",
  "geo": "US",
  "offer_id": 42,
  "domain_id": 1813,
  "group_id": 10332,
  "source_id": 836
}
```

Обязательны `name`, `geo` и положительный `offer_id`. `geo` — код страны
ISO 3166-1 alpha-2; пробелы удаляются, код приводится к верхнему регистру.
`domain_id`, `group_id` и `source_id` можно не указывать: тогда применяются
значения по умолчанию из конфигурации. Оффер и справочники проверяются до
первого запроса на запись в Keitaro.

Ответ `201` описывает созданную кампанию:

```json
{
  "id": 4812,
  "name": "Spring campaign",
  "alias": "spring-campaign-1f2e3d4c5b6a",
  "admin_url": "https://keitaro.example/admin/#!/campaign.editor/4812",
  "streams": [],
  "warnings": []
}
```

`warnings` перечисляет поля, которые Keitaro сохранил иначе, чем их отправили
(например, скорректированное название), и проблемы локального снимка. Такие
расхождения не отменяют создание; интерфейс показывает их как предупреждения.

### Повтор создания и ключ идемпотентности

Keitaro не поддерживает транзакции, поэтому `POST /campaigns` построен вокруг
одного правила: ключ освобождается только когда известно, что в Keitaro ничего
не осталось.

| Итог попытки | Статус в аудите | Ключ |
| --- | --- | --- |
| Кампания создана | `ok` | завершён, повтор возвращает сохранённый ответ |
| Запрос отклонён Keitaro (4xx) или не дошёл до записи | `failed` | освобождён, повтор создаёт кампанию заново |
| Настройка потоков или проверка не удалась, кампания удалена | `rolled_back` | освобождён |
| Кампания создана, удалить её не удалось | `rollback_failed` | сохранён |
| Ответ на запрос создания не получен (таймаут, 5xx) | `unknown` | сохранён |
| Клиент отключился до первого запроса на запись | `cancelled` | освобождён |

Пока ключ сохранён, повтор с ним отвечает `409`: тот же запрос может ещё
выполняться или уже создать кампанию, и второй запуск дал бы дубль. Пользователю
нужно проверить кампанию в Keitaro и начать новую попытку с новым ключом.

Ответ `409` содержит машино-читаемый `code`:

| `code` | Смысл |
| --- | --- |
| `idempotency_mismatch` | Ключ уже использован для другого тела запроса |
| `idempotency_pending` | Предыдущая попытка ещё выполняется или её итог неизвестен |
| `idempotency_stale` | Предыдущая попытка не завершилась больше часа назад |

Ключ в состоянии `stale` можно снять маршрутом
`DELETE /api/v1/operations/idempotency/{key}` после ручной проверки в Keitaro.

## Офферы потока

| Метод и путь | Назначение |
| --- | --- |
| `POST /api/v1/campaigns/{campaign_id}/streams/{stream_id}/offers` | Добавить оффер в поток; ответ `201` |
| `DELETE /api/v1/campaigns/{campaign_id}/streams/{stream_id}/offers/{offer_id}` | Удалить оффер из потока |
| `POST /api/v1/campaigns/{campaign_id}/streams/{stream_id}/offers/{offer_id}/restore` | Вернуть оффер, удалённый в черновике |
| `POST /api/v1/campaigns/{campaign_id}/streams/{stream_id}/push` | Опубликовать черновик в Keitaro |
| `POST /api/v1/campaigns/{campaign_id}/streams/{stream_id}/draft/cancel` | Отменить черновые изменения потока |

Тело добавления:

```json
{
  "offer_id": 42
}
```

По умолчанию (`EDITOR_PUBLISH_MODE=direct`) добавление и удаление сразу
отправляются в Keitaro: поток перечитывается, доли активных офферов
пересчитываются до суммы 100%, и `PUT /streams/{id}` заменяет массив `offers`,
сохраняя остальные настройки потока. Состояния и неизвестные поля уже
добавленных офферов передаются обратно без изменений.

В режиме `draft` те же два маршрута меняют только локальный черновик, а
`restore`, `push` и `draft/cancel` управляют его публикацией. Push
отказывается (`409`), если поток изменился в Keitaro после загрузки черновика:
правки не затирают чужие изменения. Оба режима описаны в
[конфигурации](configuration.md#editor_publish_mode).

Общие правила:

- Доли активных офферов всегда дают в сумме 100%; закреплённые доли
  сохраняются, остаток распределяется между незакреплёнными.
- Последний активный оффер потока удалить нельзя (`409`).
- Изменять офферы можно только в потоке, который их использует.
- Дубликат добавить нельзя, отсутствующий оффер удалить нельзя.
- Push не выполняется без активных офферов или с суммой долей, не равной 100%.

API аудирует добавление, удаление, восстановление, push и отмену.

## Ошибки

Все тела ошибок имеют форму `{"detail": "..."}`; для конфликтов ключа
идемпотентности добавляется поле `code`.

| HTTP | Смысл |
| --- | --- |
| `400` | Нет заголовка `Idempotency-Key` при создании кампании |
| `401` | Нет или неверен bearer-токен; см. `WWW-Authenticate` |
| `404` | Кампания, поток или оффер не найден |
| `409` | Операция конфликтует с текущим состоянием |
| `413` | Тело запроса больше 64 KiB |
| `422` | Ошибка валидации входных данных; `detail` перечисляет поля одной строкой |
| `429` | Слишком много запросов или неудачных попыток авторизации; см. `Retry-After` |
| `500` | Непредвиденная ошибка; `detail` общий, подробности — только в журнале |
| `502` | Ошибка или некорректный ответ Keitaro |
| `503` | Токен доступа к API не настроен |

Тела ошибок Keitaro клиенту не отдаются: в `detail` попадает метод, путь и
статус ответа, а само тело сохраняется в журнале backend.
