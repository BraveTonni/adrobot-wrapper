# Архитектура

Приложение — асинхронный FastAPI-сервис. HTTP-маршруты проверяют входные
данные, вызывают сценарии и формируют ответы. Сценарии работают с портом
журнала и клиентом Keitaro. Клиент изолирует HTTP-формат внешнего Admin API.

## Пакеты

| Пакет | Ответственность |
| --- | --- |
| `app/api` | Маршруты, HTTP-схемы и отображение ошибок |
| `app/domain` | Правила предметной области: коды стран и распределение долей |
| `app/services` | Создание кампаний, редактирование офферов, справочники и кэш |
| `app/keitaro` | HTTP-клиент и DTO Admin API Keitaro |
| `app/storage/models` | SQLAlchemy-модели и базовый класс ORM |
| `app/storage/database` | Создание движка и фабрики сессий |
| `app/storage/audit` | Чтение и запись журнала операций |
| `app/logging` | Настройка JSON-логирования |

`app/main.py` — composition root: создаёт инфраструктуру в `lifespan`,
сохраняет общие объекты в `app.state` и подключает HTTP-маршруты.

## Создание кампании

1. API-схема нормализует название и проверяет код страны.
2. `CampaignCreator` проверяет наличие оффера в Keitaro.
3. Сервис создаёт кампанию, гео-поток и поток оффера.
4. Сервис проверяет порядок потоков. Если настройка потоков не удалась,
   он пытается удалить созданную кампанию и записывает результат операции.
5. API формирует ответ с именами офферов и ссылкой на панель Keitaro.

Keitaro не предоставляет транзакцию для этого сценария, поэтому очистка после
ошибки является компенсирующим действием и сама может завершиться ошибкой.

## Изменение офферов

`CampaignEditor` проверяет существование оффера и принадлежность потока
кампании. Для изменения потока он читает текущее состояние, строит полный
список офферов и отправляет его в Keitaro через `PUT`. Доли распределяются
поровну и в сумме дают 100. Удалить последний оффер нельзя.

Так как API-клиент отправляет весь список, параллельные изменения между
чтением и записью могут конфликтовать. В текущей интеграции нет условной
записи или блокировки на стороне Keitaro.

## Хранение и кэш

Записи аудита хранятся в таблице `operations`; схему базы обновляет Alembic.
Справочники Keitaro кэшируются в памяти процесса с TTL из конфигурации.
Кэш не общий между несколькими экземплярами приложения.
