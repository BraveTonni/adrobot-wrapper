# Архитектура frontend

Приложение использует Next.js App Router, React и TypeScript strict. Структура разделяет маршруты, общие компоненты, функции кампаний и транспорт API:

```text
src/
  app/                         # Next.js маршруты, layout, глобальные стили
  app/styles/                  # глобальные правила и светлые/тёмные токены
  components/                  # встроенные иконки (SVG)
  components/layout/           # шапка, боковая панель, подвал, переключатель темы
  features/campaigns/          # сценарии кампаний, формы и редактор
  lib/                         # типы API и единый HTTP-клиент
```

`app/page.tsx` собирает экран из feature-компонента. `CampaignWorkspace` связывает состояние сценария с отображением. `useCampaignWorkspace` управляет загрузкой и изменением данных. Компоненты форм и редактора отображают состояние и вызывают переданные обработчики. API-запросы находятся в одном типизированном клиенте.

Все страницы и API-запросы frontend защищены HTTP Basic Auth: имя пользователя
`admin`, пароль хранится в Compose secret `frontend_auth_password`. Для локальной
разработки задайте `FRONTEND_AUTH_PASSWORD` длиной не менее 32 символов.

Иконки — встроенные SVG-контуры в `components/Icon.tsx`: интерфейс не загружает
внешний шрифт и полностью работает без доступа в интернет.

## Интеграция с backend

Браузер вызывает внутренний Next.js route handler `/api/backend/*`. Обработчик передаёт запрос backend, адрес которого берётся из серверной переменной `BACKEND_API_URL`, и добавляет Bearer-токен из серверной переменной `API_ACCESS_TOKEN` либо файла `API_ACCESS_TOKEN_FILE`. В Compose токен доступен frontend как secret-файл. Значение токена не передаётся браузеру. Проксируются `GET /api/v1/references`, `GET /offers`, `GET /campaigns?search=`, `GET /campaigns/{id}`, `POST /campaigns`, POST/DELETE для офферов и POST-действия восстановления, публикации и отмены черновика. Форматы соответствуют Pydantic-схемам backend. Ошибки API централизованно преобразуются в сообщения для пользователя.

Proxy принимает только same-origin POST/DELETE, включая действия публикации и
отмены черновика, ограничивает тело 64 KiB и не передаёт browser credentials
backend. В production публикуйте frontend только
за HTTPS reverse proxy.

Создание кампании также отправляет уникальный `Idempotency-Key`. При повторной отправке неизменённой формы используется тот же ключ, чтобы backend не создал дубль после сетевого сбоя. Изменение любого поля формы начинает новую попытку с новым ключом.

Если backend отвечает `409` с кодом `idempotency_*`, значит предыдущая попытка
ещё выполняется или её итог неизвестен. Форма показывает подсказку и предлагает
«Начать заново» — новый ключ, после того как пользователь проверил кампанию в
Keitaro. Ответ `201` может содержать `warnings`: их интерфейс показывает как
предупреждения, не отменяя созданную кампанию.

Поиск кампаний уходит в backend с задержкой 300 мс после последнего введённого
символа, чтобы не запрашивать Keitaro на каждую букву. Числовой запрос находит
кампанию по ID.

`CampaignEditor` показывает для каждого оффера название, состояние в Keitaro,
долю и ID. По умолчанию backend публикует добавление и удаление сразу, и
интерфейс сообщает, что изменения уже в Keitaro. Если backend работает с
черновиками (`EDITOR_PUBLISH_MODE=draft`), редактор показывает опубликованные и
черновые доли раздельно и выводит кнопки публикации и отмены. Кнопка удаления
последнего активного оффера отключена.

Переменная `BACKEND_API_URL` читается Next.js на сервере. Keitaro API key остаётся исключительно в backend и не передаётся браузеру.

Структура следует референсу MilkCord: маршруты собирают страницы, сценарии сгруппированы по feature, повторно используемый UI отделён, запросы и типы контрактов централизованы. Реализация адаптирована под App Router.
