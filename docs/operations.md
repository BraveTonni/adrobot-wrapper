# Эксплуатация

## Запуск

Для запуска через `make run` установите переменные окружения или создайте
`backend/.env`. В рабочей среде задавайте `KEITARO_API_KEY` через менеджер
секретов. Не храните секреты в репозитории.

Перед запуском новой версии примените миграции:

```bash
cd backend
uv run alembic upgrade head
```

Затем запустите ASGI-приложение согласно окружению. Для локального запуска
используйте `make run`; в production следует запускать Uvicorn без `--reload`
и настроить количество workers согласно инфраструктуре.

## Проверка состояния

`GET /api/health` выполняет `SELECT 1` в базе данных. Этот маршрут проверяет
доступность БД, но не проверяет соединение с Keitaro. Ошибки интеграции видны
по ответам API и структурированным JSON-логам.

`GET /api/operations` возвращает последние 50 операций: успешные изменения,
откаты и неудачные откаты кампаний.

## Миграции и данные

SQLite по умолчанию создаёт файл `backend/adrobot.db`, если команды выполняются
из `backend/`. Для другой базы задайте `DATABASE_URL`. Миграции запускаются
отдельно и автоматически при старте приложения не применяются.

Журнал операций не заменяет резервное копирование базы. План резервного
копирования выбирается для конкретной базы и среды развертывания.

## Ограничения

- Справочники кэшируются в памяти каждого процесса отдельно.
- Keitaro и локальная база не участвуют в общей транзакции. Аудит best effort:
  ошибка его записи журналируется и не отменяет уже выполненное изменение в
  Keitaro.
- Изменение offers отправляет весь список. Параллельная правка того же потока
  может быть перезаписана, так как условная запись не реализована.
